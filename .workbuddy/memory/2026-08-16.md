## CreatorHub 技能「打开页面」流畅度优化
- 实测 `opc-creatorhub open`：瓶颈在 `ensure_venv()` 每次启动都重跑 `pip install -r requirements.txt`（及 `pip install --upgrade pip`），即便 venv 已装好 —— 每次 open 约 12s，其中 ~8s 是无意义的 pip no-op 刷屏。
- 修复：`ensure_venv(force=...)` 改为幂等。新增 provisioning marker（`integrations/creatorhub/.venv/.creatorhub_provisioned`，存 requirements.txt 的 sha256）。marker 命中且 requirements 未变则完全跳过 pip；`--force` 或 requirements 变更才重装。仅 fresh venv / `--force` 时升级 pip。
- `open` 流程加反馈：launching… / already provisioned — skipping install / Waiting for CreatorHub at <url> …（探活打点）/ 就绪。
- `setup` 与 `open` 均加 `--force`（launcher 自身的 setup 也加）。
- 结果：open 12s → ~4s（实测 3.99s）；sidecar 正常启动，`/health` 即时 200，`/` 返回 app/web/index.html（真实 UI）。新增回归测试 test_launcher_provision_marker_idempotent，23 个 creatorhub 测试全过。
- 注意：改动仅本地，尚未 push。`.venv` 已存在但旧代码没写 marker，首次 open 仍会跑一次 pip 并写 marker，之后即快。
