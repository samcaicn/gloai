# 进度清单被模型当成工具调用

同一咖啡馆任务的两次真机运行里，模型都把三个验收目标放进了名为 `task_progress` 的工具调用参数，下一轮才调用查看已装 App。上游的进度约定写在回复正文的 `<task_progress>` 块里，见提交 `13f34294`。记录里的 `unknown_tool` 和缺少首条清单事件指向这两种消息格式的差异。相似的进度停滞也可能发生在模型从未生成清单时，需先查看原始回复类型和工具名。

`ProgressToolCallTest` 在运行循环入口重放这个形状。检查 `RunEvent.Criteria` 是否收到清单，实际操作是否执行一次，以及下一次模型请求中是否按原顺序为每个调用 ID 返回了结果。误放的字段仍走 `CompletionPlanBlock` 的参数和状态校验，其他未知工具仍报错。真机验收应新开同一任务；历史运行保留原有结果。

真机联测复核（2026-11-18）：52 份已捕获回复中有 4 个同名函数调用。1 个提交三项目标，另 3 个各确认一项。运行记录依次写入 4 次清单事件，未出现该工具的失败记录或进度校验错误，最终状态为 `succeeded`。联测包含逐项目标确认功能；单独应用兼容修复时，仍按所在版本原有的进度字段校验。
