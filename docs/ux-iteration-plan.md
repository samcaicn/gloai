# Jev 聊天助手（Android）体验优化与迭代方案

> 范围：Android 端（`com.jev.probe`）。目标：把「能跑通」变成「装了就留下、用着就付费」，同时不碰合规红线。
> 版本基线：v1.4 + 未发布（收银台 App 内化 / 白牌 / 分析卡死修复）。

---

## 1. 业务一页纸

| 项 | 内容 |
|---|---|
| 产品 | 挂在聊天 App 旁的「对话副驾」：读屏 + OCR → Jev 判断（意图 / 危险等级 1-9 / 该不该回 / 最佳动作）→ 生成 3 条候选并按「最合适」排序 → 悬浮窗展示 → 一键填入输入框 |
| 用户 | 需要在聊天里快速判断对方意图的人：销售 / 私域 / 客服 / 相亲 / 职场沟通 |
| 差异化 | 先判断再写字；不接管发送；截图只在本机 OCR；一个 App 一个适配器 |
| 变现 | Creem 三档：标准版月租 / 高级版月租 / 终身版。App 内 WebView 收银台（已白牌） |
| 关键机制 | **未激活 = 共享内置网关（额度有限、繁忙返回 429）；激活 = 切 worker 专属额度**（`prefs.judgeProvider = PROVIDER_WORKER`） |
| 获客 | 开源 + 官网 + 公众号/群；自配 key 用户零成本上手 |

**商业本质**：卖的不是功能，是**「不用自己配 key、不用等共享网关排队」的确定性**。
→ 因此**转化率最高的时刻不是首启，而是用户刚吃到共享网关的苦头（429 / 额度耗尽 / 排队慢）的那一刻**。

---

## 2. 北极星与成功判据

- **北极星：周成功分析会话数（WSAS）** = 每周成功产出一次判断的不同会话数。它同时被「能不能装上 / 会不会用 / 值不值得回来」三者驱动，骗不了人。
- 本方案所有 P0/P1 项，必须能落到 WSAS 或它的分解指标上；做不到就不做。

## 3. 体验现状诊断（按用户旅程）

| # | 阶段 | 用户动作 | 现状（代码事实） | 摩擦 | 严重度 |
|---|---|---|---|---|---|
| 1 | 获取 | 装 APK | 80 MB、仅 arm64-v8a、官网 + GitHub Releases | 体积大、机型受限、无渠道区分 | 中 |
| 2 | **激活** | 开 4 项权限 + 配 key | `MainActivity` 是静态清单卡，跳转后靠 `onResume` 重建；`ready = a11y && overlay && key` | **最大流失点**：4 项权限跨 3 个系统页面、无顺序引导、无「回来自动下一步」；key 要自己去第三方注册 | **高** |
| 3 | 首值 | 进聊天看判断 | 800ms debounce → 采集 →（OCR）→ 判断 → 候选 | 首值依赖外部适配质量；失败静默（如「这一屏没认出文字」），用户不知道下一步怎么办 | **高** |
| 4 | 留存 | 日常高频使用 | 状态机靠散落标志位（`analyzing` / `ocrBusy`）；无耗时、无进度、无成功/失败统计 | 刚修完的卡死即属此类；429 只报错误码无解释；用户无「有没有变好」的感知 | **高** |
| 5 | **变现** | 购买 | 入口埋在设置页深处三档按钮；收银台已 App 内化 + 白牌 | **转化时刻错配**：429 / 额度耗尽时没有升级引导；`billingUsed` / `billingQuota` 已从响应头抓到但**界面从未展示**，用户不知道还剩多少 | **高** |
| 6 | 推荐 | 公众号 / 群 | 群码普遍过期，只留公众号私信 | 口碑链路受阻，需求收集靠人肉 | 中 |

**硬伤排序**：激活（2）> 留存（4）> 变现（5）> 首值（3）> 获取（1）> 推荐（6）。

**一个必须先说的事实**：当前**零埋点**（全项目无 analytics / track / 上报）。以上排序是基于代码结构与真机观察的判断，**没有数据验证**。所以 P0 第一件事是把数据装上，否则后续所有优化都是拍脑袋。

## 4. 设计原则（硬约束，不妥协）

1. **状态永远可见**：任何时刻用户知道「在做什么 / 卡在哪 / 怎么办」，不允许静默失败。
2. **失败可自愈**：可诊断、可重试、可降级；降级后仍要给出「读到了什么」。
3. **首值 ≤ 3 分钟**：从装完到看到第一条判断，中间不允许出现「自己去注册第三方账号」。
4. **发送权在人**：`autoSend` 默认关闭、开启需二次确认、运行期有可见角标、有全局急停。
5. **合规红线**（CLAUDE.md 既有约束，本方案不越界）：不 hook / 不读库；不碰转账红包收款；截图只在本机 OCR；密钥不落日志；埋点默认关闭且**绝不上传聊天内容**。

## 5. 迭代路线

### P0 · 可观测与稳定（1–2 周）

目标：让线上问题「看得见、能定位」，消除已知的卡死与无反馈。

| 项 | 问题 | 做法 | 改动点 | 验收 |
|---|---|---|---|---|
| P0-1 | 零埋点，决策靠猜 | 加本地事件日志（环形缓冲，设备内文件，**默认关闭**）+ 可选匿名上报；字段只含事件名、耗时、结果码、App 包名，**不含聊天文本/标题明文（只存 hash）** | 新增 `core/Metrics.kt`；`ChatCaptureService` / `JudgeClient` / `ScreenCapture` 埋点 | 本地日志可导出；10 个核心事件齐全 |
| P0-2 | 状态机脆弱（卡死已修，同类隐患仍在） | 把 `analyzing` / `ocrBusy` / 各类 token 收敛成显式状态机 `IDLE → CAPTURING → OCR → JUDGING → DRAFTING → DONE/FAILED/TIMEOUT`，每态有超时与 UI 反映 | `ChatCaptureService`（已完成 analyzing 部分，继续收敛 OCR 路径） | 随机中断/切窗/关开关 20 次，无一次永久停在中间态 |
| P0-3 | 失败原因不可读 | 统一错误映射表：401 key 无效 / 429 网关繁忙或额度耗尽 / 超时 / 节点读不到 / OCR 被拒(1/2) / 未适配 App → 每类一句人话 + 一个可执行动作 | `jev/HttpJson.kt` 已有部分映射，扩展到 Overlay 展示层 | 8 类错误全部有「人话 + 下一步」 |
| P0-4 | 无法自助排障 | 一键自检卡：无障碍绑定 / 悬浮窗 / 截屏可用 / 通知监听 / key 连通 / 前台存活 / 上次分析耗时 — 输出可复制的诊断卡 | 新增 `SelfCheckActivity` 或主页卡片 | 常见 3 类故障（未开权限 / ROM 冻结 / key 错）能被用户自己定位 |
| P0-5 | 崩溃与 ANR 无感知 | 接 `Thread.UncaughtExceptionHandler` + ANR 看门狗，写本地日志（不上传） | `App.kt` | 复现一次崩溃能在本地日志里看到堆栈 |

### P1 · 首值提速与转化（3–5 周）

目标：把激活漏斗做宽，把 429 这个「最真实的付费时刻」接住。

| 项 | 问题 | 做法 | 改动点 | 验收 |
|---|---|---|---|---|
| P1-1 | 4 项权限无引导 | 引导式首启：一步一权限，跳系统页 → 回来**自动进入下一步**并打勾；未完成不显示主开关；跳过则进「轻量模式」 | `MainActivity`（`onResume` 重建机制现成） | 新用户权限全开率（目标 ≥70%） |
| P1-2 | 首值卡在「自己去注册 key」 | **新装赠送云端判断试用额度**（走内置网关，明确显示剩余 N 次）；试用期内零配置直接跑通 | Worker 侧发额度 + App 侧 `trialRemain` | 首值时间 ≤3 分钟、无需跳转第三方 |
| P1-3 | **429 / 额度耗尽 = 最佳转化时刻被浪费** | 错误态升级为「带动作的错误卡」：共享网关繁忙 → 「用专属额度，不再排队（查看档位）」直达收银台；试用耗尽 → 「继续用：选一个套餐」 | `OverlayController.showError` 增加 action 按钮 | 429 出现时的档位页点击率可测 |
| P1-4 | 额度不可见 | 设置页 + 悬浮窗顶部展示「本月已用 / 额度」进度条（数据已在 `billingUsed` / `billingQuota`，只是没展示） | `SettingsActivity` + `OverlayController` | 用户能回答「我还剩多少」 |
| P1-5 | 套餐无对比、决策成本高 | 三档对比卡：免配置 / 额度 / 是否排队 / 设备数；当前档位高亮；收银台内嵌（已完成） | `SettingsActivity` 订阅卡 | 档位页 → 收银台转化率可测 |
| P1-6 | 不知道回复好不好 | 候选卡片加「有用 / 没用」反馈，落本地，供 `tools/jev/calibrate.py` 校准，也作留存信号 | `OverlayController.replyCard` | 反馈率 ≥5%，可导出校准集 |
| P1-7 | 云端备份一直报错 | Worker `/sync` 未部署导致 `restore failed: sync HTTP 525`；要么部署，要么把失败降级为静默（当前每轮刷错误） | `wrangler deploy` + `SyncClient` 静默降级 | 无网/未部署时不再打扰用户 |
| P1-8 | 白名单不可见 | 当前会话是否在白名单、一键加入/移除 | `OverlayController` 菜单 | 减少「为什么这里不分析」的困惑 |

### P2 · 差异化与增长（6–10 周）

| 项 | 做法 | 价值 |
|---|---|---|
| P2-1 | 知识库语义检索（现在是标签/标题包含匹配） | 命中率直接决定回复质量 → 留存 |
| P2-2 | 群聊场景（现在按 1v1 分析，对群不准） | 覆盖高频场景 |
| P2-3 | 扩 App：钉钉 / Telegram / WhatsApp；提供「一键提交界面 dump」帮作者适配 | 长尾需求闭环 |
| P2-4 | 跨端同步（知识库 + 联系人，CloudSync 已具备，/sync 上线后可用） | 多设备留存与付费理由 |
| P2-5 | 包体瘦身（80 MB / arm64-only → 按 ABI 分包 + 动态下发 OCR 模型） | 安装转化 |
| P2-6 | 官网落地页与 App 内转化路径一致性改造 | 获客效率 |

## 6. 指标体系与埋点

### 指标树

- **北极星**：周成功分析会话数（WSAS）
- **激活漏斗**：安装 → 权限全开率(4/4) → 首次成功分析率 → D1/D7 留存
- **健康度**：分析成功率、端到端 P50/P90 时延、OCR 触发率与成功率、卡死/超时率、崩溃率、429 占比
- **变现**：试用耗尽率 → 档位页曝光/点击 → 收银台打开率 → 支付完成率 → 月租续费率

### 核心事件（建议最小集）

| 事件 | 时机 | 属性（均不含聊天内容） |
|---|---|---|
| `app_install_first_open` | 首次启动 | rom、abi、来源渠道 |
| `perm_state` | 每次主页可见 | a11y、overlay、notify、battery 各自布尔 |
| `perm_open_settings` | 点「去开启」 | 哪一项 |
| `analysis_start` / `analysis_end` | 一轮开始/结束 | pkg、是否手动、结果(ok/fail/timeout)、各阶段耗时、是否走 OCR |
| `analysis_fail` | 失败 | 错误类（401/429/timeout/no_text/ocr_denied）、是否展示升级引导 |
| `reply_feedback` | 点有用/没用 | rank、是否编辑后发送 |
| `license_view` / `license_buy_click` / `checkout_open` / `license_activated` | 转化链路 | tier、触发点（设置页 / 429 / 试用耗尽） |

### 基线目标（先测后定，这里给初始门槛）

| 指标 | 当前 | 3 个月目标 |
|---|---|---|
| 权限全开率 | 未知（需埋点） | ≥70% |
| 首次成功分析率 | 未知 | ≥80% |
| 分析成功率 | 未知 | ≥95% |
| P50 / P90 端到端时延 | 未知 | ≤2.5s / ≤6s |
| 卡死率 | 修复前高发 | <0.1% |
| 试用 → 付费转化 | 未知 | ≥5% |

## 7. 优先级矩阵

| | 成本低 | 成本高 |
|---|---|---|
| **影响高** | P1-3 429 转升级引导 · P1-4 额度可见 · P1-8 白名单可见 · P0-3 错误人话 | P1-1 引导式首启 · P1-2 试用额度 · P2-1 语义检索 |
| **影响中** | P0-4 自检卡 · P1-7 /sync 静默 | P2-3 扩 App · P2-5 包体瘦身 |

执行顺序建议：**P0-1 埋点 → P0-2/3/4 稳定与反馈 → P1-3/4（转化最短路径）→ P1-1/2（激活）→ P1-5/6 → P2**。
理由：先有数据，再修最痛，然后接住最真实的付费时刻，最后才做长期差异化。

## 8. 风险与边界

| 风险 | 说明 | 处置 |
|---|---|---|
| **自动发送与品牌承诺冲突** | 对外承诺「发送权永远在人手里」，但 `autoSend` 存在且可开 | 默认关；开启走二次确认；运行时悬浮窗常驻「自动发送中」角标；提供全局急停；设置页显著声明风险 |
| **隐私形象** | 产品读聊天，任何上报都会放大信任成本 | 埋点默认关闭 + 首次显式询问；绝不上传聊天文本/联系人/笔记；诊断卡由用户手动导出 |
| **平台适配脆弱** | 微信节点混淆、飞书自绘、ROM 冻结 | 适配层保持「一个 App 一个适配器」；失败必须可见且给出降级路径 |
| **付费依赖共享网关体验** | 429 既是转化机会也是体验毒药 | 免费档明确标注「共享、繁忙时排队」；429 文案不许甩锅用户 |
| **外部依赖** | Worker `/sync` 未部署、Creem webhook、Cloudflare | 全部降级为静默，绝不阻塞主链路 |

## 9. 发布与回滚

- 每 P1 项独立开关（本地 `Prefs` flag + 远程可关），灰度顺序：本人真机 → 微信群少量用户 → 全量。
- 收银台、额度、试用三项涉及钱，**先 Worker 后 App**，Worker 未就绪时 App 侧不展示入口。
- 每个版本在 CHANGELOG 用「人话」写清楚解决了什么（现行规范，保持）。
