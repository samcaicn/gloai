# No Aion words in mu: inventory

mu is its own app. Nothing a user sees may say AionUi, AionUI, AionCore, Aionrs or Aion CLI, in any of the 13 languages. This file lists every place in the desktop app that said one of them on 2026-09-23 (branch `claude/mu-no-aion`), whether a user can see it, and what was done.

How the places were found:

- Locale files: every value of `packages/desktop/src/renderer/services/i18n/locales/<13 languages>/*.json` matching `/aion/i`.
- Source: a TypeScript AST scan of `packages/desktop/src` and `packages/web-host/src` for string literals, template pieces and JSX text matching `/aion/i` (comments are not text a user sees and were not changed).
- Everything else: `grep -i aion` over `resources/`, `scripts/`, the build configuration and `public/`.

"Visible" means: on screen (text, tooltip, placeholder, aria-label, alt text), in a native dialog, the tray, the app menu, a notification, a window title or the installer, including text the local service (AionCore) sends that the app shows as it came.

## The words

| Upstream word             | In the app's own copy | In text that arrives at run time (`showAsMu`) |
| ------------------------- | --------------------- | --------------------------------------------- |
| AionUi, AionUI            | mu                    | mu                                            |
| AionCore                  | the local service     | mu                                            |
| Aion CLI, AionCLI, Aionrs | the built-in agent    | mu                                            |

Turkish suffixes follow the new last vowel (`mu'yu`, `mu'nun`), French "d'AionUi" becomes "de mu", German compounds become `mu-Installation`.

## Guards

- `tests/unit/i18n/noAionWords.test.ts`: fails when any locale value in the 13 languages contains `aion`, and when a string of the main-process files that build the window, tray, menus, notifications and dialogs contains `aion`, except an explicit list of compatibility identifiers.
- `tests/unit/kyrn/displayName.test.ts`: what `showAsMu` rewrites and what it leaves alone.

## 6. Left, and why

- The rules (system prompts) of the local service's built-in assistants, the bodies of its built-in skills, and model output still say AionUi. They are content the agent reads, not app copy; rewriting them would change what the agent is told. The Butler's rules are visible read-only in the assistant editor.
- Pages served by the local service itself: its OAuth success page (opened in the external browser) and the built-in agent's logo `aion.svg`.
- MCP server and tool ids `aionui-browser`, `aionui-image-generation`, `aionui_image_generation` and built-in skill names `aionui-*` can appear in tool cards and lists. Renaming them breaks saved configurations and the local service's matching.
- Raw backend ids used as labels in legacy data only: `aionrs` as the avatar alt/title of an old conversation with the built-in agent and no assistant (`conversationAssistantIdentity.ts` fallback), the fallback name of an old scheduled task, the runtime badge in settings. mu disables that agent at every start, so only data from before mu can show them.
- If a list ever shows the local service's built-in agent next to mu's own agent, both read "mu" (`Aion CLI` → mu). The agent management page that would do this (`renderer/pages/settings/AgentSettings/LocalAgents.tsx`) is not routed in mu.
- `/* AionUi Theme Background Start */` and `…End */` are written into the user's custom CSS and show in the CSS editor. They are how the app finds the background block; renaming them orphans blocks written before.
- Log lines keep their `[AionUi]` tags.
- Out of this app: `kyrn/` (the earlier KYRN prototype, whose footer says it is based on AionUi components), `mobile/`, `examples/`, `.github/`, README images and docs.
